# ADR 001：订单引用、资料打包与预期结果隔离

日期：2026-10-02；状态：已采用；阶段：P01 / 第 001 轮。

## 需要解决的问题

业务库应保证工单与有效订单属于同一客户，但测试还必须表达用户填写错误订单号、其他客户订单号或没有提供订单号的情况。若直接将用户输入放入订单外键，要么无法保存负面案例，要么必须放松业务完整性约束。

同时，CLI 应能从任意目录运行，业务资料应随安装包存在；Agent 不能从业务查询中看到评估预期。

## 选择

1. `supplied_order_id` 保存用户输入，仅做格式约束；`order_id` 保存核验后的关联，采用 `(order_id, customer_id)` 指向订单 `(id, customer_id)` 的复合外键。查询视图只返回当前工单客户范围内、已核验的订单资料。
2. 固定业务资料放入 Python 包的 `data/demo-v1.json`，通过 `importlib.resources` 加载并随 wheel 打包；开发案例、留出请求、gold 分别放在仓库的 `fixtures/` 与 `evals/`。
3. seed 先校验整个资料集，在单个 SQLite 事务内执行迁移和插入。重复 seed 比较资料指纹并保留已变化的业务数据，只有显式 `--reset` 才恢复演示初始资料。
4. 重置只作用于配置指向、且有本应用与 `demo` 标记的业务库。按已知表删除行并重新 seed；不删除数据库文件，不修改检查点库，不处理其他应用数据库。

## 结果与边界

- 能保存错误引用，同时维持有效关联的归属一致性。
- CLI 的本地操作员可以列出模拟工单；`order show --customer` 只是演示身份。后续服务与工具必须从可信运行上下文注入客户范围，不能把 CLI 参数当成生产认证。
- 案例文件中的故障注入只是定义，后续 runner 才执行。gold 是评估预期，不能直接用作脚本模型返回内容。
- 资料集包含故意冲突的政策，但冲突限定到特定模拟商品，不影响普通退货样例。

## 验证

测试覆盖复合外键拒绝跨客户关联、跨客户视图无订单资料、重复 seed、两个新库的一致性、迁移重复执行、初始化与重置故障回滚，以及拒绝其他数据库重置。另已构建 wheel，在独立环境和不同工作目录运行 seed 与查询，确认安装包带有业务资料且不包含 gold。
