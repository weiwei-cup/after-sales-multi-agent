# ADR 002：可信工具范围、三值规则与调查证据

日期：2026-10-02；状态：已采用；阶段：P02。

## 问题

Agent 后续会自行选择工具和参数。若客户身份、实付金额、收货时间或政策有效时间也由模型输入，模型便能改变事实或扩大访问范围。仅校验引用格式也无法发现不存在、跨工单或错误版本的证据。

## 选择

1. **应用创建调查会话**：`ToolContext` 固定工单、客户、订单候选、业务时间和 session ID；创建时再核对工单。每次调查独立创建工具实例，绑定依赖，不使用全局客户变量。CLI 是本地演示操作员入口，从工单取客户；P08 的 API 必须传入已认证身份，并核对工单所属客户。
2. **工具严格限制参数**：Pydantic 输入 `extra=forbid`。订单工具只接收 order_id，必须与当前工单引用一致；repository 使用 customer_id 再核验。政策检索只接收工单类型标签，商品和时间由应用推导。明确版本查询可用于复核，是否当前生效另行计算。
3. **事实与金额候选分开**：`evaluate_policy` 接收 order/products/tracking/history/policy 的证据引用和动作候选，退款金额可作为候选参数，必须大于零且在余额内。订单事实不能作为参数替代证据。
4. **条件计算使用代码**：单项为 true/false/unknown；逻辑合取遵循 false 优先、随后 unknown。调查报告发现任何未知条件时仍要求补资料，不自动拒绝；政策冲突优先保留并要求复核。丢件需要指定调查事件类型、可信模拟来源与不晚于业务时间的事件；自然语言描述和“缺签收凭证”不能代替确认。
5. **防止遗漏政策**：评估时重新读取同一业务时间、工单类型、商品范围与候选动作的全部有效政策。缺引用不能得到 eligible；不同条件的重叠政策保留 conflict，不默认更具体、更严格或更新的政策优先。
6. **证据采用快照**：事实保存为不可变 JSON 字符串，ID 由内容、来源、版本、时间与工单/会话范围生成。同 ID 同内容去重，内容冲突拒绝覆盖。读取与校验都检查存在性、范围、版本和所需来源类型；工具返回对象的修改不会影响已保存快照。
7. **明确执行失败边界**：没有凭证记录是查询成功且 unknown，明确缺凭证则为 missing；异常/超时无业务事实。查询工作槽有限，迟到只读结果不写证据。超长结果完整失败，不截断 JSON。所有 P02 工具与 inspection 均不写业务资料。

## 保留的边界

- P02 内存证据只在当前调查会话内有效。导出报告可供查看，不能跨进程继续引用；P06 增加持久化与恢复。
- 引用校验验证来源快照和范围，不证明自然语言结论得到语义支持，也不保证当前数据库仍与快照一致。P05 审核语义，P06 执行前重新校验资料与方案版本。
- 默认观察时间使用资料集固定时钟，以便可复现。将来真实适配器须注入实际观察时钟与服务版本。
- 超时限制调用方等待时间。Python 无法停止运行中的查询线程；每会话最多 2 个，后台读结束后才释放槽。外部服务还需驱动级 I/O 时限；全局容量在 P07 实现。
- 当前 `PolicyConditions` 的比较能发现结构化条件冲突；无法自动理解任意自然语言条款之间的矛盾。增加政策时应同步结构化条件或明确人工复核。
