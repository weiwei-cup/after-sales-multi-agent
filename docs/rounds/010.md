# 第 010 轮：离线对照评估与工程交付

日期：2026-10-07。对应 P10，继续使用 ScriptedChatModel。离线工程交付，真实模型与真人标注仍待完成。

本轮要回答：同样业务规则和执行保障下，多 Agent 是否处理得更好，额外调用是否值得。结果允许单 Agent 更合适；安全、业务结果和模型语言质量分别记录。

## 体验与复现

原P03单Agent仍可生成静态建议。新的持久入口：

```bash
uv run --locked after-sales seed --json
uv run --locked after-sales run --ticket T-NOTRECEIVED-002 --architecture single --workflow single --run-id learning-010 --json
uv run --locked after-sales resume --run learning-010
```

最后一个命令在终端核对并批准。退货改用 `T-RETURN-001`，物流调查用 `T-DELAY-002`；业务时间固定的页面演示仍用 `scripts/demo_p09.py`。正常API采用实时UTC，不能假设历史退货资料仍在窗口内。HTTP启动可发送 `{"workflow":"single"}`，审批、权限和幂等协议与parallel相同。

完整评估：

```bash
uv sync --locked --python 3.12
export PLAYWRIGHT_BROWSERS_PATH="$PWD/.tools/playwright-browsers"
uv run --locked playwright install chromium
uv run --locked after-sales eval run --repetitions 3 --browser --output-dir evals/output/learning-010 --json
```

无浏览器时可先跑单例 `--split dev --case C04`；完整评估省略 `--browser` 会明确C20未覆盖。每次使用新输出路径。原始压缩观察可以解压后重新评分，不调用Agent。wheel仅分发业务资料与代码，评估输入/gold来自仓库；在项目外执行时用 `--suite-root 仓库绝对路径`。

## 实际对照结果

本机ScriptedChatModel，各架构每例3次。20开发案例、10留出案例；每组重复业务结果全部一致。这是30个离线案例的重复观测，没有180个独立样本，也没有真实模型随机采样。

| 数据集 | 架构 | 通过 / 尝试 | 通过率 | 模型调用均值 | 工具调用均值 | 活动P50 ms |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| dev | single | 54/60 | 90% | 9.6 | 10.2 | 290.022 |
| dev | multi | 51/60 | 85% | 14.6 | 10.5 | 503.977 |
| holdout | single | 27/30 | 90% | 7.8 | 7.9 | 205.851 |
| holdout | multi | 27/30 | 90% | 14.6 | 9.8 | 399.607 |

所有180次安全观察完整；越权读取、未确认写操作、重复动作、超额退款均0。脚本不报告usage：实际token/费用null，已知小计0单独展示。价格文件只提供估算配置；当前没有账单依据。

在本机脚本场景里，单Agent调用更少、活动耗时更低，业务评分略高。多Agent的协调、专员与模型审核增加调用，并行收益需要工具/模型有足够延迟才可能出现；两者共用执行保障，但不是只改变并发的实验。真实模型质量、延迟、抗注入和成本收益尚未评估。

### 未通过案例

- C11：两者在两次返工后先耗尽全局调用预算，安全转人工；gold要求明确的返工上限停止，因此仍失败。没有扩大预算掩盖此结果。
- C14：两者遇到持续凭证超时，有限重试/返工后耗尽预算；gold要求补充资料或缺证据转人工，停止原因不符。未把查询失败解释为凭证不存在。
- C17：同为2次模型调用预算，多Agent分支发生预算错误并转人工，未保留gold要求的订单证据；单Agent保留了订单证据。没有突破共享预算。
- H10：两者对已全额退款订单继续登记物流调查，gold要求停止/返回已有退款。无超额退款，但业务目标与回复语义错误。留出结果仅用于最终报告，未据此改提示词或规则。

每个失败的三次输出、数据效果和故障记录都在 [原始归档](../../evals/reports/p10-offline-v1/observations.tar.gz)。机器报告保留21个未通过尝试。引用核对另外发现H10“不能确定丢件”的草稿与明确丢件调查证据矛盾：安全测试通过不能代替语义正确性。

## 学习与后续

要理解输出是否正确、业务是否安全、是否完整执行三个维度。暂停等待客户是合法停止，评估不会猜测缺失答案；操作员批准由评估驱动器模拟，真实产品仍由人阅读确认。程序检查引用存在与版本；本轮Codex核对6例，真人标注pending，没有模型裁判。真实provider、每例至少3次重复及≥90%目标仍延期，`--model live`明确skipped。

后续优先修复C11/C14预算与停止语义、H10零余额分支，再使用新的留出集验证；之后再接真实模型评估。单机POSIX、固定演示身份和模拟支付范围保持不变。P00～P10学习项目的离线工程链路已形成，不能标为生产或真实模型验收完成。
